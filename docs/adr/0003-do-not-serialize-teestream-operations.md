# Do not serialize TeeStream operations

TeeStream will not serialize separate operations initiated by its callers; callers that require cross-operation ordering must coordinate their own access, consistent with ordinary `Stream` ownership expectations. Within one operation, asynchronous destination calls run concurrently except for primary-sized reads. Synchronous destination calls run sequentially in destination-index order by default; concurrent mode applies consistently to every synchronous fan-out operation whenever no primary-result dependency prevents it, with primary-sized reads reading the primary first and then the remaining destinations concurrently. A mismatch under `ThrowAndContinue`, or an exception from a destination, does not remove destinations: later operations still call every destination. This deliberately favors performance and concise, auditable internals over the stronger but costly guarantee of making arbitrary concurrent caller access appear ordered.
