# Isolate TeePipe reader failures by default

When one TeePipe reader completes with an exception, the default behavior is to remove that reader from the active set and continue broadcasting to the remaining readers; an option allows applications to fail the entire pipe instead. In the default mode, the historical fault is available from that reader's indexed completion task but is not later thrown by the writer, including when the final healthy reader completes. In fail-the-pipe mode, the first concurrent reader fault becomes the pipe-wide exception, while every indexed reader-completion task retains its own reader's exception. Healthy readers may drain data that was already flushed before observing that terminal fault; their buffers are not discarded and TeePipe does not complete those readers on their behalf. This favors independent consumers and continued delivery over fail-fast coupling, while a separate completion-observation API ensures isolated failures are not silently lost.
